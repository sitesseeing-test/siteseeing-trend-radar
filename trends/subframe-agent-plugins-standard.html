Agent Plugins 1.0: Ein offener Standard bringt Design-Tools und Coding-Agenten zusammen

← Alle Trends 6. August 2026

Amazon, Microsoft, OpenAI, Vercel und Cursor haben Agent Plugins 1.0 veröffentlicht – ein offenes Format, das KI-Skills und MCP-Server in einem einzigen, wiederverwendbaren Paket bündelt. Design-Tools wie Subframe ziehen sofort nach: Ein Plugin, einmal gebaut, funktioniert damit über Claude Code, Cursor, VS Code, Copilot und ChatGPT hinweg.

Detailanalyse

Bislang mussten Teams KI-Workflows für jedes Tool separat aufbauen: eine Anleitung für Claude Code, eine andere für Cursor, wieder eine andere für den Figma-Agenten. Agent Plugins 1.0 löst das mit einem gemeinsamen Paketformat, das zwei Bausteine kombiniert – wiederverwendbare Agent Skills für Anweisungen und Workflows sowie MCP-Server, die den Agenten an konkrete Tools und Daten anbinden. Initiiert von Vercel, gemeinsam verfeinert mit AWS, Anysphere (Cursor), GitHub, Microsoft und OpenAI, ist der Standard direkt in VS Code, Copilot, Cursor, ChatGPT und Kiro integriert; Google ist am selben Tag als Core Maintainer beigetreten.

Für Design-Tools ist das unmittelbar praxisrelevant: Subframe bündelt seinen MCP-Server und eigene Agent Skills bereits in einem Claude-Code-Plugin, das Designs abruft und neue Konzepte generiert – installiert einmal, nutzbar in mehreren Coding-Agenten gleichzeitig. Bemerkenswert ist die Leerstelle in der Trägerkoalition: Anthropic, das die zugrunde liegende Agent-Skills-Spezifikation ursprünglich entwickelt hat, fehlt in der Liste der Core Maintainer.

Ein Plugin, neun Clients: Genau dieses Versprechen – einmal bauen, überall einsetzen – ist der Kern von Agent Plugins 1.0 und macht firmeneigenes KI-Workflow-Wissen erstmals portabel zwischen Tools.

Für Design-Teams verschiebt sich damit die Frage von "welches KI-Tool nutzen wir" zu "welche Skills bauen wir einmal richtig". Wer heute noch Prompt-Bibliotheken pro Tool pflegt, arbeitet nach diesem Standard doppelt – zukünftig zahlt sich aus, Workflow-Wissen als portables Skill-Paket zu dokumentieren statt als Tool-spezifische Anleitung.

Für Siteseeing

Internes Workflow-Wissen einmal als Skill bauen, überall einsetzen

Siteseeing arbeitet bereits mit Claude Code, Figma und weiteren KI-Agenten im Alltag – bislang aber vermutlich mit tool-spezifischen Anweisungen und Prompts, die bei jedem neuen Tool erneut aufgebaut werden müssen. Mit Agent Plugins 1.0 lässt sich das eigene Design-System-Wissen – etwa Komponenten-Konventionen, Barrierefreiheits-Checks oder das Siteseeing-eigene Briefing-Format – einmal als Skill paketieren und in Claude Code, Cursor und künftig weiteren Tools identisch wiederverwenden. Das reduziert Einarbeitungszeit für neue Teammitglieder und macht die eigene Methodik zu einem wiederverwendbaren Asset statt verstreuter Tribal Knowledge.

Sofortmaßnahme

Diese Woche eine bestehende, häufig genutzte interne Anleitung (z. B. Design-System-Konventionen oder Accessibility-Checkliste) als erstes eigenes Agent-Skill-Paket dokumentieren und in Claude Code testen.
