CSS Scroll-Triggered Animations: Nativ in Chrome 145 – kein JavaScript mehr nötig

← Alle Trends 5. Juni 2026

Chrome 145 bringt Scroll-Triggered Animations als natives CSS-Feature: Animationen können nun direkt per CSS ausgelöst werden, wenn ein Element den Viewport passiert – ohne IntersectionObserver, ohne JavaScript-Libraries. Das vereinfacht einen der häufigsten Interaktionspatterns im modernen Webdesign erheblich.

Detailanalyse

Bisher benötigten Scroll-Animationen – Elemente, die einblenden, wenn sie in den sichtbaren Bereich scrollen – stets JavaScript: entweder über die IntersectionObserver API oder externe Libraries wie GSAP, AOS oder Animate.css. Mit Chrome 145 hält die neue CSS-Property animation-trigger Einzug, die es ermöglicht, Animationen deklarativ zu steuern: Eine Animation startet, wenn ein Element einen definierten Scroll-Threshold passiert, pausiert, wenn es sich außerhalb befindet, und setzt sich fort oder setzt zurück, je nach Konfiguration.

Scroll-Triggered Animations sind die logische Ergänzung zu den bereits seit Chrome 115 verfügbaren Scroll-Driven Animations, die Animationen proportional zur Scroll-Position verbinden. Während Scroll-Driven Animations kontinuierlich mit dem Scroll-Fortschritt arbeiten (z.B. Parallax-Effekte), sind Scroll-Triggered Animations zeitbasiert: Sie werden an einem definierten Punkt ausgelöst und laufen dann unabhängig vom Scrollverhalten ab. Typische Anwendungsfälle sind Fade-ins beim Erscheinen von Content-Blöcken, Hero-Animationen, die beim Einblenden eines Abschnitts starten, oder Lottie-ähnliche Effekte ohne externe Abhängigkeiten.

Chrome 115 (2023) brachte Scroll-Driven Animations, Chrome 145 (2026) ergänzt Scroll-Triggered Animations – zusammen decken sie nahezu alle gängigen scroll-basierten Interaktionspatterns in purem CSS ab.

Die Browser-Kompatibilität ist der entscheidende Faktor für den praktischen Einsatz: Chrome 145 liefert Entwicklerinnen und Entwicklern das Feature nativ, aber Firefox und Safari folgen erfahrungsgemäß mit Verzögerung. Für Produktionsprojekte empfiehlt sich bis zur breiten Unterstützung ein Progressive-Enhancement-Ansatz: Das native CSS-Feature als bevorzugte Lösung, JavaScript als Fallback. Die Sitepoint-Analyse zeigt, wie bereits heute ganze Carousel-Komponenten ohne JavaScript in purem CSS realisiert werden können – ein Vorgeschmack auf die nächste Evolutionsstufe des Webdesigns.

Für Siteseeing

Performance-Vorteil als Verkaufsargument: Weniger JavaScript, schnellere Seiten

Für Siteseeing-Kunden, deren Websites auf Performance-Metriken wie Core Web Vitals optimiert werden sollen, ist dieser Trend direkt relevant: Jede JavaScript-Library, die durch natives CSS ersetzt wird, reduziert Bundle-Size, verbessert Ladezeit und verringert das Risiko von Rendering-Blocking. Kunden aus dem Mittelstand, die gerade Website-Relaunches planen, können von Siteseeing das Argument hören: Moderne Interaktivität ohne JavaScript-Overhead. Das ist kein technisches Detail – das ist eine messbare Verbesserung von SEO-relevanten Metriken.

Sofortmaßnahme

In einem aktuellen Kundenprojekt eine bestehende IntersectionObserver-basierte Einblend-Animation identifizieren und als CSS-only-Variante mit animation-trigger neu implementieren – als interne Proof-of-Concept-Demo, die zeigt, wie viel Code und Ladezeit eingespart werden kann.
