Figma Code Layers & Specs: Prototyp und Spezifikation wandern auf den Canvas

← Alle Trends 16. Oktober 2026

Figma macht den Canvas zum Ort, an dem Code und Anforderungen entstehen. Mit Code Layers in der offenen Beta und den neuen Specs als Markdown-Container verschwimmt die Grenze zwischen Designdatei, Prototyp und Ticket.

Detailanalyse

Auf der Config im Juni hatte Figma Code Layers noch als geschlossene Beta vorgestellt. Am 15. Oktober folgte die offene Beta: Prototypen lassen sich aus einem GitHub-Repository oder einem lokalen Ordner importieren, über den Figma-MCP-Server aus Coding-Tools übernehmen, per Chrome-Extension von Live-Seiten erfassen oder aus bestehenden Frames erzeugen. Änderungen gehen als Branch samt Pull Request zurück ins Repository. Auf bezahlten Plänen ist das Erstellen und Bearbeiten von Code Layers bis zum 4. November kostenlos, danach werden KI-Credits abgerechnet.

Parallel startet Specs, ebenfalls als offene Beta für bezahlte Pläne. Markdown-Dateien werden per Drag-and-drop zu Spezifikationen auf dem Canvas, in die sich Frames, FigJam-Boards und Code Layers einbetten lassen. Der Figma-Agent beantwortet Kommentare darin, und Coding-Agenten wie Codex lesen eine Spec mitsamt verlinktem Kontext über den MCP-Server. Ein GitHub-Connector zieht Codebasis-Wissen in technische Specs, ein Hex-Connector beantwortet offene Datenfragen direkt als Kommentar.

Merkle berichtet von 30 % schnellerer Iteration und 50 % weniger Dokumentation wie Interaktions-Specs in Tickets, seit das Team mit Code Layers arbeitet.

Für Designteams bedeutet das: Die Übergabe besteht künftig weniger aus Redlines und Ticket-Prosa, sondern aus einer lebenden Spec und einem lauffähigen Prototyp im selben Dokument. Wer dabei vorne liegt, braucht saubere Markdown-Strukturen, Designsysteme mit Code Connect und klare Regeln, wer Code-Branches anlegen darf. Spannend wird die Abrechnung ab November, denn jede Agent-Iteration im Code Layer kostet dann Credits.

Für Siteseeing

Spec-first-Übergaben als Leistungspaket anbieten

Siteseeing-Kunden kämpfen oft mit dem Bruch zwischen UX-Konzept, Jira-Tickets und Entwicklung. Mit Specs und Code Layers kann Siteseeing eine Übergabe anbieten, in der Anforderung, Design und lauffähiger Prototyp in einer Figma-Datei liegen und direkt von den Coding-Agenten der Kundenteams gelesen werden. Das ist ein greifbares Argument für Retainer-Kunden mit eigenen Entwicklerteams: weniger Rückfragen, schnellere Umsetzung, nachvollziehbare Entscheidungen.

Sofortmaßnahme

Bis zum 4. November, solange Code Layers noch kostenlos sind, ein laufendes Kundenprojekt auswählen, eine Seite als Code Layer aus dem Kunden-Repo importieren und eine dazugehörige Spec anlegen – Zeitaufwand und Rückfragen im Vergleich zur bisherigen Übergabe dokumentieren.
