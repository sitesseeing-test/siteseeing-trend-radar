CSS Anchor Positioning: Tooltips ohne JavaScript – Baseline 2026

← Alle Trends 12. Juni 2026

Eine der lästigsten Frontend-Aufgaben der letzten Jahrzehnte ist endlich gelöst: Das Positionieren von Tooltips, Dropdowns und Popovers relativ zu anderen Elementen erledigt der Browser jetzt nativ. CSS Anchor Positioning hat 2026 den Baseline-Status erreicht und wird vollständig in Chrome, Firefox und Safari unterstützt – ohne eine einzige Zeile JavaScript.

Detailanalyse

CSS Anchor Positioning ermöglicht es, ein Element per CSS an ein beliebiges anderes Element im DOM zu verankern. Der Browser übernimmt automatisch Overflow-Awareness, Viewport-Grenzen und Flip-Fallbacks. Die zentralen Eigenschaften sind überschaubar: `position-anchor` (welches Element ist der Anker), `position-area` (wo relativ zum Anker positionieren) und `position-try-fallbacks` (alternative Positionen, wenn kein Platz ist). Was früher 150 bis 200 Zeilen JavaScript-Eventlistener, ResizeObserver und Popper.js erforderte, löst jetzt ein halbes Dutzend CSS-Deklarationen.

Konkret bedeutet das das Ende von Floating UI, Popper.js und Tippy.js für neue Projekte. Chrome und Edge unterstützen Anchor Positioning seit Version 125 (Juni 2024), Firefox seit Version 147 (Anfang 2026), Safari seit Version 26. Die Anwendungsfälle sind breit: Tooltips, Dropdown-Menüs, Context-Menus, Autocomplete-Listen und Notification-Bubbles – alles, was bisher eine JavaScript-Library als Pflichtdependency hatte. Für Produktionsprojekte gilt: Anchor-Positioning-CSS in `@supports (anchor-name: --foo)`-Blöcke einwickeln, damit ältere Browser sauber auf statisches Layout zurückfallen.

150+ Zeilen JavaScript für ein einfaches Tooltip schrumpfen auf wenige CSS-Deklarationen – und der Browser rechnet Positionen performanter als jede JS-Library.

Anchor Positioning gilt bereits als das bedeutendste neue Layout-Primitive seit Flexbox und Grid – weil es ein Problem löst, das ein Jahrzehnt lang JavaScript-Workarounds zwang. Für neue Projekte 2026 gibt es keinen sachlichen Grund mehr, Popper.js oder Floating UI in der `package.json` zu behalten. Die Feature-Detection ist trivial und der Fallback auf statisches Layout in den meisten Fällen akzeptabel.

Für Siteseeing

JS-Tooltip-Bibliotheken in neuen Projekten aktiv ersetzen

Siteseeing-Entwickler können bei neuen Projekten und Redesigns Popper.js und Floating UI gezielt ersetzen und so Bundle-Size sowie Dependency-Overhead messbar reduzieren. Das ist kein Selbstzweck: Weniger Abhängigkeiten bedeuten weniger Sicherheitslücken, schnellere Build-Zeiten und geringeren Wartungsaufwand. Der Performance-Gewinn lässt sich gegenüber Kunden konkret kommunizieren – und Anchor Positioning ist ein überzeugendes Beispiel dafür, dass modernes CSS oft mehr leistet als externe Libraries.

Sofortmaßnahme

Im nächsten laufenden Projekt, das Tooltips oder ein Dropdown-Bauteil enthält, CSS Anchor Positioning mit `@supports`-Fallback implementieren und Popper.js bzw. Floating UI als Dependency entfernen – als internen Proof of Concept, der zeigt, wie viele Codezeilen und Package-Größe gespart werden.
